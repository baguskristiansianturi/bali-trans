# Roadmap — BDM Trans / Bali Trans

**Updated:** 17 October 2026  
**Active branch:** `preview/bali-trans`

## Current direction
Restart the visual design from a single homepage. Use Klook-like discovery UX as a reference, but create a distinctive BDM identity rather than a generic monochrome template.

- [x] Remove old secondary-page prototypes from the preview branch for a clean reset; Git history is preserved.

- [ ] Confirm latest Pages deployment is successful.

## Stage 2 — Homepage approval
- [ ] Improve art direction, photography, typography, spacing and mobile hierarchy based on actual visual review.
- [ ] Check all visible controls and search filtering in a browser.
- [ ] Replace the generic WhatsApp destination with the actual business contact number.
- [ ] Verify any claims, offers, prices, suppliers and booking promises before publishing them.

## Stage 3 — Minimal site structure (only after homepage approval)
- [ ] Decide which secondary pages are genuinely required.
- [ ] Write each page's copy and purpose before coding it.
- [ ] Add navigation destinations only when those pages exist.
- [ ] Restore only validated routes and test all links.

## Guardrails
- Do not mark a deployment as successful until Actions confirms it.
- Do not claim manual visual/device testing unless it happened.
- Do not invent inventory, prices, testimonials, supplier status or booking availability.
- Avoid decorative clutter, redundant cards and monochrome sameness.
- Keep preview noindex until launch policy is deliberately changed.
